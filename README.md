# LinuxLab — интерактивная PWA для обучения Ubuntu

Полностью автономный, статический тренажёр для системного администратора, на русском языке.

## Что включено

- **14 учебных модулей** с короткой теорией и примерами.
- **151 упражнение** с ручным вводом команд и проверкой без выполнения.
- **16 смоделированных инцидентов** со стадиями расследования и терминальным выводом: systemd, Nginx, DNS, SSH, TCP, диск, inode, OOM, Docker, TLS и т. п.
- **4 уровня**: новичок, базовый, продвинутый, эксперт. В фильтре кейсов три уровня.
- Интервальное повторение 1 / 3 / 7 / 14 / 30 / 60 дней, поиск слабых мест, экзамен.
- План на главной подбирает до пяти заданий с учётом дневной цели. Сначала идут повторения по сроку, затем новые команды по уровню сложности из разных модулей.
- 200 интерактивных разборов вывода Linux с выбором темы и примера, объяснением каждого варианта и переходом к ручному вводу той же команды. Итог тренировки позволяет сразу повторить задания с ошибкой, подсказкой или пропуском.
- Два самостоятельных ответа по расписанию убирают команду из списка сложных. Повторный ответ до срока сохраняет текущий интервал. Решение одного задания приносит XP и засчитывается в дневную цель один раз в день.
- 73 записи в справочнике, XP, дневная цель, график активности, локальное сохранение, экспорт и импорт прогресса.
- Service Worker и web manifest: после первой загрузки под HTTPS можно работать офлайн.

## Открыть или установить

[Открыть LinuxLab](https://everves.github.io/linuxlab/) можно в обычной вкладке на компьютере, планшете и телефоне. Для работы офлайн сначала откройте сайт с сетью и дождитесь статуса «Готов к работе без сети» в настройках.

- **Windows, macOS и Linux** — в Chrome или Edge выберите установку LinuxLab в меню браузера, если она доступна. В Safari на macOS выберите «Файл» → «Добавить в Dock».
- **Android** — в меню браузера выберите установку или добавление на главный экран.
- **На iPhone и iPad** — откройте приложение в Safari и выберите «Поделиться» → «На экран Домой» → «Добавить».

Уроки и инциденты можно сохранить в закладки и отправить ссылкой. После выхода новой версии приложение предложит закрыть и снова открыть все его вкладки. Пройденные задания, очередь повторения и XP сохраняются в текущем браузере. Для переноса прогресса используйте «Настройки» → «Экспорт» и «Импорт».

## Запуск и проверки

Соберите статические файлы с Node.js 24 и запустите локальный сервер на Windows, macOS или Linux.

```sh
npm run build
npm run serve
```

Откройте [локальную сборку](http://127.0.0.1:4173/linuxlab/). Установка npm-пакетов нужна только для браузерных тестов.

```sh
npm test
npm ci
npx playwright install
npm run test:browser
```

## Публикация на GitHub Pages

В **Settings → Pages → Build and deployment → Source** выберите **GitHub Actions**. Workflow запускает проверки в pull request, а после успешных проверок ветки `main` публикует `dist/`. Версия офлайн-кэша вычисляется при сборке по содержимому файлов. Содержимое `dist/` также можно разместить у другого статического HTTPS-хостинга.

## Техническое устройство

- `index.html`, `styles.css`, `app.js` — интерфейс.
- `content.js` — уроки, тренировочные задания и сценарии. Ключи заданий перед первым `§` сохраняются при перестановке строк и используются для привязки прогресса. Не переиспользуйте старый ключ для другого задания.
- `answers.js` — сравнение с допустимыми ответами и подсказки по ошибкам. Поддерживаемые короткие флаги можно группировать и менять местами. Варианты команд для отдельного задания добавляются через `‖`.
- `learning.js` — подбор заданий, интервалы и признаки сложных команд.
- `readings.js`, `reading-cases.js` — каталог примеров вывода, варианты ответов и пояснения. Каждый разбор имеет собственный стабильный ID и привязан к упражнению на ввод команды.
- `progress.js` — схема прогресса версии 1 и проверка бэкапов.
- `routes.js` — адреса страниц в части URL после `#`.
- `sw.js`, `pwa.js`, `manifest.webmanifest`, `icons/` — установка, офлайн и уведомление об обновлении.

## Важные ограничения версии 1

- **Это симулятор, а не терминал Ubuntu**: произвольные Linux-команды не исполняются. Сценарии ожидают определённые диагностические шаги. Альтернативные валидные варианты могут не распознаваться — проверку можно расширить.
- Проверка команд не является полноценным shell-парсером. Некоторые варианты написания флагов и синонимы могут потребовать добавления в `content.js`.
- Прогресс хранится в браузере локально и может потеряться при очистке данных сайта. Делайте резервные копии.
- Для синхронизации между устройствами, живого терминала, AI-оценивания и генерации бесконечных кейсов потребуются backend и модель или песочница. Реальные команды на прод-серверах никогда не стоит выполнять без явного разрешения и изоляции.
- В экзамене ошибки валидации учитываются как неправильный ответ; это отличный режим для закрепления точного синтаксиса, но не сертификация.
